# META-USAGE: використання інструментів штучного інтелекту

Документ виконує вимогу п. 11.4 методички: команда T01 описує, де і як під час роботи над `SimpleArchiver` використовувалися інструменти ШІ, і що зроблено власноруч.

## 1. Де застосовувався ШІ

| Напрям | Що саме робив ШІ | Як перевіряла команда |
|---|---|---|
| Форматування документації | вирівнювання Markdown-таблиць, однакова структура розділів `README.md`, `docs/report/REPORT.md`, `docs/decisions.md`, виправлення друкарських помилок і стилю | кожен абзац вичитано автором розділу, усі числа звірено з `experiments/FULL_REPORT_TABLES.md` і логами |
| Шаблони звітних таблиць | заготовки заголовків колонок для таблиць 1–5 (TSV/Markdown) і для порівняльних таблиць ГА, NSGA-II, витоку метаданих | значення в таблицях генерує лише програма (`report`, `ga`, `pareto`, `leak-table`, `attack`); вручну чисел не вписано |
| Генерація граничних автотестів | пропозиції граничних випадків: порожній файл, вироджений алфавіт, файл рівно в розмір блока, зіпсований байт тому, неправильний пароль, обрізаний том, небезпечні імена `../`, недомінованість точок фронту Парето, елітизм ГА | кожен запропонований тест переписано під наш API, запущено `dotnet test SimpleArchiver.slnx`; тести, що перевіряли неправильну поведінку, відкинуто |

ШІ **не** використовувався для вибору алгоритмів і не був джерелом результатів експериментів: усі виміри отримано запуском програми на `data/` викладача.

## 2. Що реалізовано і верифіковано командою власноруч

Усі алгоритми курсу написано членами команди, перевірено контрольними точками (`check`), автотестами та взаємним Code Review через Pull Request-и в `main`:

| Алгоритм | Де в коді | Чим перевірено |
|---|---|---|
| Коди Гаффмана (дерево, канонічні коди, таблиці LIT/LEN/DIST) | `src/SimpleArchiver/Huffman/` | контрольна точка «Гаффман», контрольний блок специфікації, `Stage1Tests` |
| LZ77: жадібний, лінивий і ДП-розбір | `src/SimpleArchiver/Compression/Lz77.cs`, `MatchFinder.cs` | контрольна точка «ДП-розбір» (ДП не гірший за жадібний і лінивий), таблиця 1 |
| ДП-розбиття на блоки | `src/SimpleArchiver/Compression/BlockSplitter.cs` | контрольна точка «ДП-розбиття», таблиця 1 |
| ДП-рюкзак 0/1 і жадібний за `v/w` | `src/SimpleArchiver/Packing/` | контрольна точка «Рюкзак» (ДП 10, жадібний 7), таблиця 3 |
| Перцептрон (класифікатор типу файла) і прогноз байта | `src/SimpleArchiver/Analysis/` | контрольні точки «Перцептрон» (чисельний градієнт) і «Прогноз байта», macro-F1 на `valid/` |
| AES-256-CTR + HMAC-SHA256 (Encrypt-then-MAC), PBKDF2, Діффі — Геллман | `src/SimpleArchiver/Crypto/`, `src/SimpleArchiver/Format/Volume.cs` | еталонні та зіпсовані архіви викладача (`ref-check`, 12 з 12), `SecurityTests` |
| Генетичний алгоритм (базовий і просунутий), випадковий і локальний пошук | `src/SimpleArchiver/Optimization/GeneticOptimizer.cs` | контрольна точка «Генетичний алгоритм», `Stage3Tests` (елітизм, рівний бюджет Q) |
| Фронт Парето (NSGA-II за `(S, T)`) | `src/SimpleArchiver/Optimization/ParetoOptimizer.cs` | контрольна точка «Фронт Парето», тест взаємної недомінованості |
| Модуль атаки (XOR/Віженер через ГА, метадані, цілісність) | `src/SimpleArchiver/Crypto/WeakCipherAttack.cs` | `SecurityTests` (злам ключа, вирівнювання, відмова `E_HMAC`) |

## 3. Правила, яких дотримувалася команда

1. Жоден фрагмент, запропонований ШІ, не потрапляв у `main` без Pull Request-у і рецензії іншого учасника.
2. Кожен учасник має пояснити на захисті будь-який рядок свого коду; код, який автор не міг пояснити, переписувався.
3. Числа у звіті беруться лише з файлів у `experiments/`, які створює програма.
4. Інженерні рішення і причини змін записано в `docs/decisions.md`.
